Issue #8: поддержка Markdown в письмах — показ входящих с частью text/markdown и что уходит при отправке. Редактор в режиме Markdown — в макете #24. Пометка предложение — деталь, которой нет в issue; открытый вопрос — показаны варианты.

1. Входящее письмо с Markdown-частью

В письме три части: text/plain, text/html и text/markdown. Над письмом справа — переключатель «HTML · Markdown · Текст», того же вида, что «Все · Люди · Рассылки» над списком. По умолчанию выбран вид из настройки «Показывать письма» (кадр 4). Выбор в письме действует, пока оно открыто, и не запоминается предложение (решение: только общая настройка + переключатель в письме).

Markdown рисуем сами, теми же стилями, что и вложения .md (pulldown_cmark): заголовки, списки задач, таблицы, код с подсветкой, цитаты. Внешние картинки в Markdown — по тем же правилам, что в HTML-письмах (скрыты до разрешения).

4. Настройки → «Почта» → «Чтение»

Одна общая настройка, три значения (решение: без настроек по ящику и по отправителю). По умолчанию — «Как прислал отправитель» предложение: это правило MIME (последняя понятная часть — предпочтительная), и при нём Markdown-письма от «Депеши» сразу показываются как Markdown. Страница в приложении называется «Почта» (в задаче — «Письма»).

5. Какие части уходят: строка в режиме Markdown предложение

Тихая строка над нижней панелью — только в режиме Markdown, где набор частей отличается от привычного. По щелчку — пояснение со структурой письма. В режимах «Текст» и «HTML» строки нет. Режимов «только plain + markdown», «по возможностям получателя» и запоминания по контакту из исходного текста #8 нет (решение).

Обычные клиенты покажут HTML или текст. «Депеша» и клиенты, понимающие Markdown, — исходник с разметкой. Отключить Markdown-часть — в настройках «Почта → Новые письма» открытый вопрос
multipart/alternative ├─ text/plain; charset=UTF-8 ├─ text/html; charset=UTF-8 └─ text/markdown; charset=UTF-8; variant=CommonMark
Что уходит из каждого режима предложение

Решение: text/plain + text/html всегда (кроме режима «Текст»), text/markdown — только если письмо написано в режиме Markdown. Выбора набора частей в окне нет.

Текст
text/plain — как сейчас

HTML
multipart/alternative ├─ text/plain └─ multipart/related — если есть картинки ├─ text/html └─ image/png; Content-ID — картинки текста и подписи

Markdown
multipart/alternative ├─ text/plain ├─ text/html — из Markdown (pulldown_cmark) └─ text/markdown; variant=CommonMark

Markdown — последней частью: по MIME это «предпочтительный» вид, клиенты, которые его не знают, возьмут HTML. Вложения — снаружи, в multipart/mixed, как сейчас.
