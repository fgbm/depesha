# Решения по макетам 0.6.0

Согласовано с оператором 2026-10-05. Макеты — HTML-файлы рядом; номера кадров по порядку в файле.

## Общие

- Страница ящика в настройках: одна прокручиваемая страница с разделами «Общее · Письма и подписи · Хранилище · Сервер» и оглавлением-якорями сверху; подключение свёрнуто в «Общем».
- Готовые фильтры (#16) и закрытые ожидания (#37) — через операторы поиска и готовые запросы в Ctrl+K и подсказках поиска; закрытые — переключатель «Активные / Закрытые» внутри «Ждут ответа». Новых пунктов в сайдбаре нет, сохранённых поисков нет.
- Вне 0.6.0: квота через EWS; метки, ACL и выбор папки в возможностях сервера; отдельные подписи для новых и ответов; формат по получателю и 4 уровня показа Markdown.

- Палитра `Ctrl+K` сортирует команды по последнему использованию: недавние сверху (в пустом запросе и при равной релевантности совпадения). Делается вместе с #16, который добавляет в палитру готовые запросы.

## #16 Крупные письма

- Размер в строке списка — всегда, приглушённо (кадр 2, вариант Б); при сортировке по размеру — тёмным и жирным.
- Порог «крупного письма» — настройка (кадр 6, вариант Б), 25 МБ по умолчанию; готовые запросы берут его.
- Операторы с русскими синонимами: `больше:`/`larger:25M`, `меньше:`/`smaller:`, `старше:`/`older:1г`, `новее:`/`newer:`, `год:`/`year:2024` (с 1 января до 1 января следующего, исключительно), `в:Работа/*` — папка с подпапками (сам `in:` поведения не меняет), `ящик:`/`account:`.
- Готовые запросы — в подсказках поля поиска («Готовые запросы», «Недавние», памятка операторов) и в `Ctrl+K`. Кнопки «Готовые поиски» в заголовке списка и сохранённых поисков нет.
- Если в запросе есть `больше:`, сортировка сама становится «Крупные сначала».
- Итоги над результатами «N писем · X ГБ (по кэшу)» и «На сервере»; в панели выделения «Выбрано N писем · X МБ» и «Выбрать все найденные».

## #15 Квота

- Только IMAP (QUOTA); у Exchange в «Хранилище» тихое «нет данных».
- Индикатор в сайдбаре — всегда: под папками ящика мелкая приглушённая строка «3,1 из 10 ГБ» с тонкой полоской, клик открывает «Хранилище» ящика (кадр 7, вариант А).
- У порога та же строка становится жёлтой и получает процент, при 100 % — красной (кадр 8, вариант А). В полосе узкого окна (#38) — цветное кольцо у кружка ящика (кадр 12).
- Пороги 90 / 95 / 100 %, общие для всех ящиков, в «Настройки → Уведомления»; в ящике — только свой лимит (кадр 14).
- 90 и 95 % — тост в приложении с «Найти крупные письма» (открывает `больше:` с порогом из настроек #16); системное уведомление при свёрнутом окне — только при 100 % (кадр 9).
- «Хранилище» в настройках ящика: занято / лимит / процент со шкалой, «по данным сервера, обновлено …», локальный кэш отдельно и подписан как локальный, свой лимит, «Посчитать размер папок» только по кнопке, как фоновая задача (кадр 1).
- Подсчёт размера папок: `STATUS=SIZE`, если сервер умеет, иначе сумма размеров писем.

## Страница ящика

- Одна страница: оглавление «Общее · Письма и подписи · Хранилище · Сервер» (прилипает, подсвечивает текущий раздел); у Exchange без «Сервера».
- «Общее»: название, имя отправителя, адрес, цвет ящика (переезжает сюда со страницы «Все ящики»), папка для вложений; «Подключение» свёрнуто, в заголовке сводка и состояние.
- «Сохранять копию отправленных» — внутри «Подключения».
- Кнопки общие для страницы; «Сохранить» становится «Проверить и сохранить», только если менялось подключение.

## #11 Возможности сервера

- Раздел «Сервер»: таблица «Функция — что даёт — сервер — Депеша», группы «используется / есть на сервере, Депеша не использует / нет на сервере / объявлено, но не заработало»; у проблем строка «Без этого…» (кадры 1–2).
- «Технические подробности» свёрнуты: сырой CAPABILITY, ответ на ENABLE, неизвестные расширения, «Скопировать», «определено …», «Проверить снова» (кадр 3).
- Жёлтая точка у пункта «Сервер» в оглавлении, если нет IDLE или MOVE.
- Сырой CAPABILITY и время определения хранятся в кэше — раздел работает без сети.
- Для Exchange раздел скрыт.

## #24 Редактор письма

- Формат по умолчанию: у существующих установок текст, у новых HTML; ответ — в формате ящика.
- Картинки в теле HTML-письма — в 0.6.0; одна сборка `multipart/related` для тела и подписи.
- Переключатель «Текст · HTML · Markdown» — в строке «От» (кадр 2, вариант Б); в узком окне сворачивается в «HTML ▾».
- Цитата в HTML-ответе — внутри редактора, `blockquote` в тексте (кадр 8, вариант А).
- Картинки: при перетаскивании две зоны «Вставить в текст / Прикрепить файлом», плюс кнопка «Картинка» и вставка из буфера (кадр 5) — оба способа.
- Подтверждение при смене формата — только HTML → «Текст»; Markdown → «Текст» без вопроса (кадр 9).
- Быстрый ответ — простое поле без переключателя (кадр 10).

## #25 Подписи

- Несколько подписей на ящик, одна по умолчанию; список в «Письма и подписи» с меню «⋯» (кадр 1). Редактор — тот же, что в #24, без переключателя режима; картинка из файла и из буфера, предупреждение выше ~200 КБ, текстовая версия для режима «Текст» (кадры 2–3).
- Выбор подписи в письме — меню на самом блоке подписи; если подпись убрана, тихая строка «Без подписи · добавить ▾» (кадр 4, вариант Б).
- Смена отправителя ставит подпись нового ящика по умолчанию, даже если до этого подпись выбирали вручную (кадр 5).
- Править подпись внутри письма нельзя: блок нередактируемый, его можно только убрать или заменить другой подписью.

## #8 Markdown

- Переключатель «HTML · Markdown · Текст» над входящим письмом — только если в письме есть часть `text/markdown` (кадр 3, вариант А).
- Настройка «Показывать письма» в «Почте»: по умолчанию «Как прислал отправитель»; ещё «Предпочитать Markdown», «Предпочитать текст» (кадр 4).
- Отправка: `text/plain` + `text/html` всегда, `text/markdown` — только для письма, написанного в режиме Markdown; флажка «не отправлять Markdown» нет; тихая строка о составе частей в режиме Markdown (кадр 5).
- Отдельного вида «Исходный Markdown» нет — вид «Markdown» и есть исходник. Редактор Markdown как в Obsidian (Live Preview) — отдельной задачей после 0.6.0 (#45).

## #37 «Ждут ответа»

- Переключатель «Активные / Закрытые» внутри вида (сегмент, как «Все / Люди / Рассылки»), а не фильтр в меню «Вид».
- Название варианта мелко в первой строке строки списка (кадр 2, вариант А).
- Повтор «и потом каждые N дней до ответа» — поле сохранённого варианта (кадр 6, вариант А); выбор при отправке остаётся в один клик.
- Отдельный срок «Ответ нужен к» и вид «За N до срока» — делаем (кадр 7, вариант А).
- Пункт «Ждут ответа» в сайдбаре виден, пока есть хоть одно ожидание — активное или закрытое.
- «В понедельник в 9:00», отправленное в понедельник до 9:00, — следующий понедельник (не раньше чем через сутки).
- Закрытые хранятся 90 дней; срок хранения — настройка (Настройки → Напоминания), 90 по умолчанию.
- Кнопка «Снова ждать ответа» у закрытого.
- Без god object: логику «Ждут ответа» не сваливать в один разросшийся модуль или структуру (ни в `AppStore`, ни в один огромный `store.rs`-блок/плагин) — раскладывать по отдельным модулям с узкой ответственностью.
