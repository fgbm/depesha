Как узнаём, что трея нет

На сессионной шине D-Bus нет org.kde.StatusNotifierWatcher — значит, значок libayatana-appindicator никто не покажет. Так бывает в чистом GNOME (Fedora, Debian, Arch). В Ubuntu расширение AppIndicator стоит по умолчанию, в KDE, Cinnamon, XFCE, MATE трей есть.

Проверяем при запуске и при каждом закрытии: расширение могут включить и выключить на ходу.

Если трея нет, в «Настройки → Общие» под «Закрытием окна» — жёлтая строка: «В этой системе нет значков в трее. Скрытое окно открывается повторным запуском Депеши.» (кадр 5).

Повторный запуск уже ведёт в работающую копию (single-instance, lib.rs): нужно только добавить show() к unminimize + set_focus — та же общая функция, что для клика по уведомлению (#63, п. 4).

  • А — issue требует явного подтверждения работы в фоне без значка. + Честно и по issue. − Человек может не знать, что «снова запустить» = открыть окно.
  • Б — «×» сворачивает окно вместо скрытия. + Окно никогда не теряется, работает везде. − «Закрыть» не закрывает; окно занимает место в Alt+Tab и в обзоре.
  • В — GNOME 44+ показывает фоновые приложения в быстрых настройках, с кнопкой «×» = выйти. + Родной для GNOME способ. − Работает только для Flatpak-сборки (портал различает приложения по песочнице); для .deb/.rpm/AppImage — нет. Проверить на живом GNOME.
  • Рекомендация А для обычных сборок; если появится Flatpak — В вместо А.
