# Решения по макетам 0.7

Согласовано с оператором 2026-10-07. Решения принял оператор по HTML-макетам рядом; номера кадров по порядку в файле. Опрос тестировщиков (`poll.md`) — дополнительный: на решения влияет только по согласованию с оператором.

## #4 Работа в фоне и трей

- Первое закрытие окна крестиком: спросить, с флажком «Запомнить выбор» (`01-background-notifications.html`, кадр 1, вариант А) — во всех установках.
- Linux без трея: предупредить и спросить (кадр 3, вариант А). Flatpak не собираем — пользователей нет.
- Настройки: отдельная страница «Фон и запуск» (кадр 5, вариант Б), на ней же автозапуск при входе в систему — с окном или в фоне.
- Бейдж на значке трея: число (кадр 6, вариант А), считаем все непрочитанные, а не только письма от людей. Число рисуется на самой иконке: по итогам спайка трей не показывает подпись рядом со значком.
- Меню значка: короткое (кадр 7, вариант А). Из варианта Б берём пункт «Показать N непрочитанных» — он есть только при непрочитанных и заменяет строку состояния.
- Поправка по спайку к кадру 8: на Linux через KSNI левый щелчок по значку открывает окно, меню — на правом.
- Щелчок по значку при открытом окне — как в Telegram: окно не впереди → вывести вперёд, окно впереди → скрыть.
- Выход, когда в «Исходящих» есть письма по расписанию: спросить (кадр 9, вариант А). Плюс тост из варианта Б с «Отправить сейчас» при следующем запуске, если письмо пропустило срок по любой причине, например компьютер был выключен.
- Основы из спайка (для #4 и #63): трей через `tray-icon` с бэкендом `ksni`; уведомления — notify-rust на Linux, tauri-winrt-notification на Windows; автозапуск — tauri-plugin-autostart с `--background`; закрытие окна прячет окно, а не уничтожает его. Ручная проверка: Wayland/GNOME (подъём окна), Windows 11 (тёмное меню трея, щелчок из Центра уведомлений).

## #63 Щелчок по уведомлению

- Уведомление: отправитель, тема, ящик, без текста письма (кадр 10, вариант А). Кнопок действий в 0.7 нет.
- Несколько писем: одна сводка на все ящики (кадр 11, вариант В).
- Куда ведёт щелчок по письму: остаться в текущем списке, если письмо там видно, иначе «Входящие» ящика (кадр 12, вариант В). Строка подсвечивается рамкой, которая гаснет за 1,5 с.
- Щелчок по сводке: открыть «Входящие» без выбора письма (кадр 13, вариант А); при сводке на все ящики открываются «Все входящие», а не «Входящие» отдельного ящика. Новые письма слегка подкрашены, пока список открыт; при уходе из списка подкраска исчезает (принцип «список не прыгает», `docs/ux.md`, п. 7). Список прокручен в начало.
- Письма уже нет: тост «…перенесли или удалили» с кнопкой «Найти» (кадр 14, вариант А).
- Если в момент щелчка открыты «Настройки» или модальный диалог — закрыть их без сохранения.
- Когда окно Депеши в фокусе, системное уведомление не показывать.
- При выходе убирать уведомления Депеши из Центра уведомлений Windows — желательно (кадр 15).

## #55 Отметки ответа

- Значки как скрепка: 13 px, серые, последними перед датой (`02-queue-and-reply-marks.html`, кадр 2, вариант А).
- Если на письмо ответили и ответили всем — один значок «ответ всем», как более полный; в подсказке оба действия.
- Подсказка с временем (кадр 3, вариант Б). Время действия храним. Если отметка пришла с сервера (ответ из другого клиента) — «отметка сервера, время неизвестно».
- Узкий список: кадр 4, вариант А. Шапка письма: кадр 5, вариант А.
- В разделе «Ждут ответа» значка ответа и статуса справа достаточно.

## #59 «Входящие» как очередь

- «Ждут ответа» — одна сущность «ожидание» (кадр 9, вариант А).
- Включение: настройка ящика с выбором папки плюс флажок в окне письма (кадр 6, варианты А + В). По умолчанию выключено. Функция для тех, кто ведёт почту как тикет-систему.
- «Не ждать»: по умолчанию вернуть во «Входящие»; в настройках можно переопределить на «в Архив».
- «Входящие» — только папка с ролью inbox, без подпапок.
- Переносится вся цепочка, а не только письмо, на которое ответили (отличие от текста #59).
- Когда письмо уходит из списка: строка остаётся с меткой, пока с неё не ушли (кадр 7, вариант Б).
- Тост: кадр 8, вариант А. Ответ не из «Входящих»: кадр 12, вариант Б. Нет прав создать папку: кадр 13, вариант А.
- Метка «пришёл ответ» (кадр 11, вариант А) живёт до открытия письма.

## #45 Live Preview

- Под курсором раскрывается только элемент, а не вся строка (`03-markdown-editor.html`, кадр 4, вариант Б, как в Typora).
- Таблица: правка прямо в ячейках (кадр 6, вариант Б). Как в Obsidian, сверху и слева ручки строк и столбцов: добавить, удалить, переместить.
- Картинки в тексте Markdown-письма разрешены (кадр 7, вариант А). На бэкенде это встраивание в само письмо, а не вложение. Кнопка «Картинка» возвращается в Markdown.
- «Просмотр» переделывается в «Разметку», показывающую всю разметку разом (кадр 8, вариант Б).
- Метка «Markdown» (кадр 10): в окне письма будет кнопка переключения режима, которая заодно показывает текущий режим. Вторая итерация макета сделана — решение кнопка формата в подвале (`06-markdown-editor-v2.html`, кадр 6, вариант Б).
- CodeMirror 6 подключаем в 0.7 по итогам спайка: свои декорации, ленивый чанк, свой набор синтаксиса под pulldown-cmark (без Subscript, Superscript, Emoji, Autolink). После 0.7 решаем, оставить его или писать своё.
- Подсветка синтаксиса в блоках кода делается в 0.7 (кадр 5).
- Подсветка синтаксиса только на клиенте. Пока набираешь, подсвечивает редактор (CodeMirror). Когда Депеша показывает Markdown-письмо (своё или входящее), подсветку делает фронтенд до передачи HTML в MailFrame: тот же разбор lezer из ленивого чанка ставит классы, а стили лежат в srcdoc. Скриптов в iframe нет.
- В уходящем HTML подсветки нет: адресат получает обычный `<pre><code>`. Разбор цветов на Rust (syntect) отклонён.
- HTML для отправки редактор не выдаёт: письмо и у нас, и у адресата собирается одной функцией на бэкенде.
- Набор языков небольшой, общий для редактора и чтения.
- Таблица: правка в ячейках плюс ручки строк и столбцов (`06-markdown-editor-v2.html`, кадры 1–2). Появляется двумя способами: набором `| … |` и Enter, и пунктом «Таблица» в «⋯» строки оформления (кадр 3, А + Б). Широкая таблица прокручивается вбок (кадр 4, А). Удаление всей таблицы — пункт в меню ручек, плюс выделить и Del.
- Кнопка формата: в подвале рядом с «⋯», кнопка с меню «HTML / Markdown / Текст», её подпись показывает текущий режим (кадр 6, Б). Пункты формата из меню «⋯» убираются. Это уточняет прежнее решение #45 про «кнопку переключения режима вместо метки Markdown».
- Смена формата с набранным текстом: вопрос только при HTML → Текст, иначе тост с «Отменить» (кадр 8).
- Описание картинки — alt, правится в панели (кадр 10, Б).
- Размер картинки — как в HTML, без размера в разметке (кадр 11, А).
- Большие картинки при вставке: если картинка inline, уменьшать; порог и поведение вынести в настройки (предпочтительнее, чем спрашивать каждый раз). Конкретный порог (1600 px) — в настройках как значение по умолчанию.
- Кнопки «Заголовок» и «Код»: строка оформления как в HTML, а эти две — в её «⋯» (кадр 16, В). Плюс сочетания Ctrl+1/2/3 для заголовков и Ctrl+E для кода через реестр команд #46.
- Подпись: одна HTML-подпись на все форматы (кадр 14, А). В тёмной теме подпись показывается как есть (кадр 13), то же для HTML-писем.

## #44 Формат по адресату

- Карточка человека заводится (кадр 11, вариант В) вместе с адресной книгой, где можно править данные. Список правил формата в «Настройки → Почта» (кадр 11, вариант Б) убран: вместо него короткая сводка со ссылкой на страницу «Люди». Формат для адресата задаётся в карточке человека.
- Формат переключился по правилу: тихая строка с «Вернуть HTML» (кадр 12, вариант А).
- Несколько адресатов: кадр 13, вариант А.
- Вид входящих: кадр 14, вариант А, плюс настройка ящика (кадр 15).
- После ручной смены формата предлагать правило — да. Правила только по адресам, без доменов.
- Если человек сам присылает Markdown, предлагать «писать ему в Markdown» — да. Таких подсказок будет много, поэтому нужен единый механизм подсказок.

## #42 Метки, права, свойства папок

- Метки в письмах берём в 0.7 целиком; доводка — в патч-релизах.
- Метки в строке письма — ярлыки после темы (кадр 10, вариант А), не точки у даты.
- Подраздел «Папки» — список всех папок (`04-server-labels-acl.html`, кадр 2, вариант А).
- Свойства папки — карточка у папки (кадр 4, вариант А).
- Общие папки — отдельной группой по владельцу (кадр 6, вариант Б).
- Запрещённое действие: неактивная кнопка с подсказкой (кадр 7, вариант А) плюс отметка «Только чтение».
- Прочитанное в папке только для чтения хранить локально.
- Кнопки «Проверить все папки» нет.
- Ключи меток — свои имена, без совместимости с Thunderbird `$label1–5`.
- Exchange (права из EffectiveRights, категории) делаем в этой же задаче, предварительно изучив документацию.
- Окно настроек сделать больше — размером как развёрнутое на весь экран окно нового письма. Это отдельная задача.

## #46 Сочетания клавиш

- Редактор — страница «Клавиши» в настройках (`05-keybindings.html`, кадр 1, вариант А).
- Вход в редактор клавиш из палитры команд по Alt+Enter нужен: открывает страницу «Клавиши» на строке этой команды (кадр 1, вариант В — только вход, основное место остаётся страница настроек).
- Запись сразу по нажатию на «Переопределить», без кнопки «Сохранить» (кадр 5, вариант А). Конфликт — кадр 7, вариант А.
- Ctrl+K не переназначается.
- Запрещены только Ctrl+C/V/X, остальное разрешено.
- Последовательностей «g, затем i» нет (кадр 9, вариант А).
- Двойная подпись `e у` везде: страница, меню, палитра, подсказки (кадр 10, вариант Б — во всех местах, а не только в настройках).
- Несколько клавиш на команду — кнопка «+» остаётся.
- Показывать все команды, в том числе без клавиши.
- Конфликт с плагином: клавишу сохраняет тот, кто занял её первым (кадр 13).
- Импорта, экспорта и готовых наборов нет.
- Перед UI нужен единый реестр команд и клавиш (сейчас четыре места и подсказки в строках перевода).

## #68 Окно настроек большего размера

- Размер: 1040 px в ширину и высота окна минус 64 px, отступы как у развёрнутого окна письма (кадр 1).
- Навигация: меню страниц слева, над ним поиск «Найти настройку» (кадр 2, вариант А).
- Ширина содержимого: одна колонка до 680 px (кадр 5, вариант А).
- Сохранение — уточнение: оператор сказал дословно «сохранять настройки надо на текущей странице». Значит, у каждой страницы своё сохранение, нижнюю строку «Сохранить / Отмена» не прячем. Это закрывает вопрос макета про автосохранение страниц «Клавиши» и «Люди».

## #66 Адресная книга и карточка человека

- Книга — страница настроек «Люди» (кадр 9, вариант А).
- В книгу попадают все адреса из переписки. Отдельного типа «рассылка» в 0.7 нет: все адреса — обычные записи книги, как люди. Спрятать запись можно вручную. Если книга станет шумной из-за noreply и рассылок, это отдельная задача позже, не в 0.7.
- Щелчок по имени отправителя открывает карточку; в ней первая кнопка «Все письма» (кадр 12, вариант А).
- Объединение адресов одного человека («это один человек?») — не в 0.7, отдельной задачей позже.

## #69 Единый механизм подсказок

- Тихая строка там, где подсказка касается дела (кадр 14, вариант А).
- Лимиты приняты: одна подсказка за раз, не больше трёх в день, пауза 14 дней после «Не сейчас», затем подсказка затихает, один общий выключатель (кадр 16).
- Список принятых и отклонённых — раздел «Подсказки» на странице «Общие» (кадр 17, вариант А).
- Подпись кнопки согласия — само действие, а не «Да»: например, «Писать в Markdown». То же для других подсказок: подпись кнопки называет действие.
