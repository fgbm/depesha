# Корпус писем для проверки отправителя (0.8.13)

Каталог `crates/depesha-core/tests/sender/` — обезличенные заголовки настоящих писем и таблица того, что каждое письмо должно решать. Автотест `crates/depesha-core/tests/sender_trust.rs` читает таблицу и сверяет её с лестницей доказательств (`crates/depesha-core/src/sender.rs`).

## Что в каталоге

| Файл | Что это |
| --- | --- |
| `table.json` | Таблица: письмо → ящик → ступень лестницы → картинки → логотип → причина. |
| `*.txt` | Блок заголовков письма, как его отдал сервер ящика. |
| `*-original.txt` | Исходные заголовки письма Exchange (`PR_TRANSPORT_MESSAGE_HEADERS`, `0x007D`) — то, что покрывает подпись. |
| `keys/s1.pkcs8` | Закрытая половина ключа, которым подписаны два письма корпуса (PKCS#8 DER в base64). Ключ испытательный: вне этих файлов он ничего не подписывает. |

## Как обезличить

Подпись при обезличивании ломается, поэтому в корпусе два слоя: заголовки после обезличивания и решение, записанное до него.

- Адрес ящика получателя → `me@box.example`.
- Имя получателя → «Получатель».
- Адреса машин внутри `Received` → `192.0.2.x` (RFC 5737) и `2001:db8::x`.
- `From`, `Date`, `DKIM-Signature` и `Authentication-Results` сервера — **не меняются**: это то, что читает проверка отправителя. `Message-ID` лучше заменить на выдуманный, но формат оставить.
- Тело письма в файле Exchange (`exchange-ews-*.txt`) — пересобрано, как его собирает Exchange: границы частей другие, кодировка перенесённая, тема в quoted-printable. Именно из-за этого хэш тела не сходится.

Подпись обезличенного письма пересчитать нельзя: она покрывает те заголовки, которые обезличивание меняет. Поэтому два письма корпуса, где подпись нужна (ступени 3 и 4), подписаны ключом из `keys/s1.pkcs8` — `DkimSigner` из `mail-auth`, по RFC 6376, как подписывает почтовая программа. Ключ публикуется проверке вместо name server (`dkim::Verifier::add_answer`), так что тест не ходит в DNS и проверяет настоящую подпись, а не её вид.

Переписать подписи после правки письма:

```
cargo test -p depesha-core --test sender_trust -- --ignored sign_the_corpus
```

## Как добавить письмо оператора

1. **Снять письмо.** В Депеше: меню письма → «Сохранить заголовки для отладки» (или блок заголовков из IMAP-клиента). Для Exchange — блок `0x007D` вместе с исходными заголовками.
2. **Обезличить** по правилам выше и положить в каталог под понятным именем: `gmail-<отправитель>.txt`, `yandex-<отправитель>.txt`, `exchange-ews-<отправитель>.txt`.
3. **Не ломая подпись.** Если письмо с Exchange в своей сети — положить исходные заголовки отдельно, `exchange-ews-<отправитель>-original.txt`. В `exchange-ews-<отправитель>.txt` — то письмо, каким его отдал сервер: подписи в нём нет, тело пересобрано. Если обезличивание требует правки подписанных заголовков, письмо в корпус не годится: подпись перестанет сходиться, и тест будет врать.
4. **Записать решение** строкой в `table.json`: ящик (`gmail`, `yandex`, `mailru`, `exchange-online`, `exchange-ews`, `own-imap`), `From`, ступень (`1`, `2`, `3`, `4`, `-`), картинки (`true`/`false`), логотип (`true`/`false`) и причина, когда никто не подтвердил (`server`, `unsigned`, `signature`, `unchecked`, `no_check`).
5. **Проверить.** `cargo test -p depesha-core --test sender_trust`. Тест идёт по таблице и сверяет её с лестницей; строку, которой нет в таблице, тест не проверяет. Итог тест не берёт из таблицы: он делает те же проверки, что окно (`dkim::offline_verdict`, `dkim::Verifier::check`, `dkim::check_headers`, `sender::body_check`), и сравнивает ответ лестницы с записанным.

## Стенд

Стенд получает по-настоящему подписанное письмо (`e2e/fixtures/dkim_sign.py`, ключ `e2e/fixtures/dkim-key.pem`): подпись по RFC 6376, своим ключом. У стенда нет name server, поэтому ключ публикуется приложению вместо них — команда `e2e_publish_dkim_key` (только в сборке `e2e`). Своя проверка подтверждает письмо — ступень 3 лестницы, и логотип отправителя встаёт в строке списка.

## Чего корпус не проверяет

- Чужие подписи: у писем корпуса ключ свой, а векторы настоящих отправителей (RFC 8463, RFC 6376, ietf.org, github.com) лежат в `crates/depesha-core/tests/dkim-vectors/` и проверяются в `dkim.rs`. Там же — `t=y`, `rsa-sha1`, `l=`, `adkim=s`, истечение `x=`, `i=` и ключ, которого нет.
- Хэш тела: на ступени 4 тела нет — письмо проверено по заголовкам, и в этом весь смысл ступени.
- То, что сервер ящика на самом деле пишет: это проверяется на живых ящиках по таблице ручной приёмки в `docs/acceptance.md` (раздел «Проверка отправителя перед меткой»).
