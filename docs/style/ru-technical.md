# Правила русского технического языка

Русские тексты Депеши пишутся по этим правилам. Правила построены на тех же принципах, что и ASD-STE100 для английского: ограниченный словарь, один термин для одного понятия, короткие предложения, одна инструкция в шаге. Английские тексты — по правилам [ste-en.md](ste-en.md).

## 1. Охват

Правила действуют для русских текстов, которые читает человек: `README.md`, документы в `docs/`, тексты русского интерфейса, сообщения об ошибках, описания коммитов на русском.

Комментарии в коде пишутся по-английски, правила — в `AGENTS.md`, раздел «Code rules».

## 2. Слова

<!-- vale off -->

1. Словарь терминов — в [`docs/glossary.md`](../glossary.md). Не дублируй его здесь и не заменяй термин синонимом.
2. Словарь проверяет `scripts/ste-lint.mjs`: он даёт ошибку на запрещённый синоним и на пустое слово.
3. Пиши общеупотребительные слова в прямом значении. Не используй переносные значения и метафоры.
4. Не нанизывай отглагольные существительные. Не пиши «выполнение проверки наличия обновлений» — напиши «проверь, есть ли обновления».
5. Не используй слова «просто», «легко», «очевидно», «пожалуйста».
6. Для обязательного требования пиши «должен». Не пиши «желательно» и «рекомендуется» о том, что обязательно.
7. Названия команд, параметров, файлов и элементов интерфейса не переводи. Оформляй их как код: `depesha-core`, `--no-bundle`.

## 3. Предложения

1. Предложение в инструкции — не длиннее 20 слов.
2. Предложение в описании — не длиннее 25 слов.
3. Абзац — не длиннее 6 предложений.
4. Пиши в действительном залоге. «Депеша отправляет письмо», а не «письмо отправляется Депешей».
5. Не используй причастные и деепричастные обороты, если без них можно обойтись. Разбей фразу на два предложения.
6. Одна мысль — одно предложение.
7. Абзац и пункт списка — одна строка, какой бы длинной она ни была. Перенос — только между блоками: заголовки, абзацы, пункты списка, таблицы, блоки кода. Проверяет `scripts/md-onelines.mjs`.

## 4. Инструкции

1. Одно действие — один шаг.
2. Документы для людей — на «вы»: «Откройте файл». Тексты для агентов (`AGENTS.md`, `docs/agents/`) — на «ты»: «Открой файл».
3. Условие ставь вперёд: «Если ящик не на связи — выполните шаг 4».
4. Предупреждение ставь до шага, к которому оно относится.
5. Нумеруй шаги.

## 5. Примечания и предупреждения

| Тип | Когда использовать | Пример |
|---|---|---|
| Предупреждение | Риск потери данных или проблема безопасности. | «Не стирайте папку: письма не вернуть». |
| Внимание | Риск повредить настройки или ящик. | «Не закрывайте окно, пока идёт фоновая задача». |
| Примечание | Полезные сведения без риска. | «Плагин запускается, только когда вы его откроете». |

Сначала короткий запрет или команда, затем причина: «Не стирайте папку. Письма не вернуть».

## 7. Проверочный список

Используй этот список при каждой проверке русского текста:

- [ ] Длина каждого предложения в пределах нормы.
- [ ] В каждом шаге одно действие в повелительном наклонении.
- [ ] Действительный залог.
- [ ] Каждое понятие обозначено одним термином из словаря.
- [ ] Нет канцелярита, жаргона и слов-паразитов.
- [ ] Предупреждения стоят до шагов.
- [ ] Абзац и пункт списка — одна строка.
- [ ] `scripts/md-onelines.mjs` не показывает нарушений.
