# Критерии приёмки Депеши 1.0

Версия 1.0 принимается, когда выполнены все критерии с пометкой **[обяз.]**. Пометка **[жел.]** — желательно, не блокирует выпуск. В колонке «Проверка» указано, как подтверждается критерий: **авто** — автотест против GreenMail в CI (`compose.test.yaml`), **Exchange** — ручной прогон на живом Exchange 2019, **ручн.** — ручная проверка на любом сервере.

Целевые серверы: Exchange 2019 (on-premises), Яндекс Почта, Mail.ru, Gmail (пароль приложения), Timeweb, Dovecot/Postfix. OAuth2 в 1.0 не входит.

## 1. Учётные записи

| № | Критерий | Проверка |
| --- | --- | --- |
| 1.1 | **[обяз.]** Мастер добавления: адрес и пароль, затем автоопределение серверов. Порядок: известные провайдеры → autoconfig (`autoconfig.<домен>`, ISPDB Thunderbird) → SRV (`_imaps._tcp`, `_submission._tcp`) → перебор `mail.<домен>`, `imap.<домен>`, `smtp.<домен>` на 993/143 и 587/465. Найденные параметры показываются, их можно исправить вручную. | ручн., авто (перебор) |
| 1.2 | **[обяз.]** Перед сохранением мастер проверяет вход по IMAP и SMTP и показывает понятную причину отказа. | авто |
| 1.3 | **[обяз.]** Пароль хранится в связке ключей ОС (Secret Service / Keychain / Credential Manager). В файлах настроек, базе, логах и сообщениях об ошибках пароля нет. | авто (grep по профилю), ручн. |
| 1.4 | **[обяз.]** Несколько учётных записей одновременно; удаление учётной записи стирает её кэш и пароль. | авто, ручн. |
| 1.5 | **[обяз.]** Логин может отличаться от адреса: `user@domain`, `DOMAIN\user`, `DOMAIN\user\shared` (общий ящик Exchange). Обратная косая черта передаётся без искажений. | авто, Exchange |

## 2. Шифрование и сертификаты

| № | Критерий | Проверка |
| --- | --- | --- |
| 2.1 | **[обяз.]** IMAP: TLS (993) и STARTTLS (143). SMTP: TLS (465) и STARTTLS (587). Сертификат проверяется по системному хранилищу. | авто, Exchange |
| 2.2 | **[обяз.]** Ошибка сертификата не принимается молча. Пользователь видит причину (истёк, не то имя, неизвестный издатель), срок действия и SHA-256 отпечаток. Может доверить **именно этот** сертификат для этой учётной записи; при смене сертификата вопрос задаётся снова. | авто (самоподписанный), Exchange |
| 2.3 | **[обяз.]** Если сервер не предлагает STARTTLS (например, receive-коннектор Exchange без сертификата), клиент не отправляет пароль открытым текстом. Пользователь видит объяснение «сервер не поддерживает шифрование». Незашифрованное подключение возможно только по явной галочке в настройках учётной записи, с предупреждением. | авто |
| 2.4 | **[обяз.]** Если сервер не предлагает поддерживаемый способ входа (например, только `GSSAPI NTLM`), сообщение называет предложенные механизмы. NTLM и Kerberos в 1.0 не реализуются. | авто |

## 3. Синхронизация (IMAP)

| № | Критерий | Проверка |
| --- | --- | --- |
| 3.1 | **[обяз.]** Список папок с вложенностью; русские имена отображаются корректно (modified UTF-7). | авто, Exchange |
| 3.2 | **[обяз.]** Роли папок определяются по SPECIAL-USE, а без него — по именам, включая имена Exchange: «Входящие», «Отправленные» / Sent Items, «Удаленные» / Deleted Items, «Черновики» / Drafts, «Нежелательная почта» / Junk Email, «Архив» / Archive. | авто, Exchange |
| 3.3 | **[обяз.]** Служебные папки Exchange без почты скрыты по умолчанию: Календарь, Контакты, Задачи, Заметки, Журнал, Проблемы синхронизации (с подпапками), Исходящие, RSS-каналы, Журнал бесед, а также английские аналоги. Ошибка в такой папке не ломает синхронизацию остальных. | авто, Exchange |
| 3.4 | **[обяз.]** Первая синхронизация папки с 50 000 письмами показывает последние 500 писем быстрее чем за 30 секунд; более старые подгружаются при прокрутке. | авто (генератор), Exchange |
| 3.5 | **[обяз.]** Новое письмо появляется в списке не позже чем через 60 секунд без ручного обновления: IMAP IDLE, без него — опрос раз в 2 минуты. IDLE перезапускается не реже раза в 25 минут: Exchange рвёт неактивные сессии. | авто, Exchange |
| 3.6 | **[обяз.]** Обрыв связи, `* BYE`, смена сети или сон ноутбука: клиент переподключается сам, ничего не дублирует и не теряет. | авто (kill контейнера), ручн. |
| 3.7 | **[обяз.]** Изменения, сделанные в другом клиенте (OWA, Outlook, телефон), — прочитано, флаг, перенос, удаление — видны после следующей синхронизации. | авто, Exchange |
| 3.8 | **[обяз.]** Смена UIDVALIDITY сбрасывает кэш папки и загружает его заново. Действие, поставленное в очередь до смены (флаг, перенос, удаление), к другим письмам с теми же UID не применяется: флаг ставится заново на те же письма по Message-ID, перенос и удаление отклоняются с понятной ошибкой. То же для папки Exchange, кэш которой собран заново. | авто |
| 3.9 | **[обяз.]** На одну учётную запись не больше 3 одновременных IMAP-соединений (лимит Exchange — 16 на пользователя). | авто |
| 3.10 | **[обяз.]** После отказа во входе (неверный пароль, недоверенный сертификат, сервер без TLS) автоматические попытки прекращаются до действия пользователя: повторы раз в несколько минут блокируют доменную учётную запись по политике AD. | авто |
| 3.11 | **[обяз.]** Действие, которое ждёт ответа сервера (открыть письмо не из кэша, отметить, перенести, «Готово», удалить, поиск на сервере), во время полной синхронизации ждёт не дольше синхронизации одной папки или одной пачки офлайн-загрузки, а не всех папок. Синхронизация после него продолжается с оставшихся папок, ни одна не пропускается и не проходится дважды; задача «Синхронизация» одна на проход. Два действия подряд выполняются в порядке отправки. | авто (очередь воркера), ручн. |
| 3.12 | **[обяз.]** На «сервер занят» (`ErrorServerBusy`, троттлинг EWS) клиент не шлёт запросы раньше паузы `BackOffMilliseconds` из ответа; без неё ждёт 5 секунд, удваивая паузу, пока сервер занят; пауза не больше 5 минут. Соединение не сбрасывается и вход не повторяется. Действие пользователя ждёт паузу до 5 секунд, при более длинной сразу получает «сервер занят, повторите через N с». Ящик не встаёт на паузу, синхронизация продолжается сама. | авто (скриптованный EWS, очередь воркера), Exchange |

## 4. Чтение

| № | Критерий | Проверка |
| --- | --- | --- |
| 4.1 | **[обяз.]** Общий входящий по всем учётным записям, отдельные папки, фильтры «непрочитанные» и «с флагом». | авто, ручн. |
| 4.2 | **[обяз.]** Кодировки UTF-8, Windows-1251, KOI8-R в теме, адресах, теле и именах вложений, в base64 и quoted-printable, отображаются без «кракозябр». | авто (фикстуры) |
| 4.3 | **[обяз.]** HTML показывается в изолированной области: скрипты, формы, iframe и обработчики событий вырезаются; ссылки открываются в системном браузере с показом настоящего адреса. | авто, ручн. |
| 4.4 | **[обяз.]** Удалённые картинки по умолчанию не грузятся, есть кнопка «показать» для письма и «всегда для отправителя». Доверие действует, только когда подлинность отправителя подтвердил сервер ящика (DMARC в его `Authentication-Results`, у Exchange — внутренняя почта организации); письмо с тем же `From` без подтверждения показывается без картинок. Встроенные (`cid:`) картинки показываются сразу. | авто, ручн. |
| 4.5 | **[обяз.]** Вложения: список с размерами, сохранить, открыть системным приложением, сохранить все. С папкой для вложений (в настройках или у ящика) «Сохранить» и «Сохранить все» пишут в неё без диалога, не затирая файлы с тем же именем; «Сохранить как…» спрашивает место. Приглашения (`.ics`) и вложенные письма (`.eml`) показываются как вложения. | авто, ручн. |
| 4.6 | **[обяз.]** Открытие письма не ставит «прочитано» до показа; «прочитано» и «флаг» переключаются вручную и уходят на сервер. | авто |
| 4.7 | **[обяз.]** Уже открытые письма читаются без сети. | ручн. |
| 4.8 | **[жел.]** `winmail.dat` (TNEF) раскрывается во вложения. | ручн. |
| 4.9 | **[жел.]** Группировка в цепочки по `References` / `In-Reply-To`. Место цепочки при сортировке по дате и дату в строке задаёт последнее входящее письмо: свой ответ цепочку не поднимает (в «Отправленных» — своё последнее письмо). Отправленный ответ появляется в цепочке без смены папки, в том числе на Exchange и Gmail, где копию кладёт сервер. | авто |
| 4.10 | **[жел.]** Вложения просматриваются внутри приложения, в области чтения на месте текста письма (список и строка вложений остаются видны, показанное вложение подсвечено), одной оболочкой для всех форматов: картинки, PDF, Word, таблицы, Markdown, HTML, CSV в любой из русских кодировок, текст, вложенные письма; ←/→ между вложениями, Esc закрывает; документы без скриптов и сети; неизвестный формат предлагается открыть в приложении. | авто |
| 4.11 | **[жел.]** Письмо открывается в отдельном окне двойным щелчком; ответ пишется в этом окне; «Готово» и удаление закрывают окно, отмена — в главном. | авто |
| 4.12 | **[жел.]** Письмо с частью `text/markdown` показывается с переключателем «HTML · Markdown · Текст» над текстом (в узком окне — выпадающий список); у остальных писем его нет, пока настройка не показала письмо не так, как прислал отправитель. Markdown рисует «Депеша»: заголовки, таблицы, код, цитаты, списки задач с неактивными галочками; очищается как HTML, внешние картинки — по тем же правилам. Markdown-часть — не вложение. Настройка «Почта» → «Чтение» → «Показывать письма»: как прислал отправитель (по умолчанию), предпочитать Markdown, предпочитать обычный текст; выбор в письме действует, пока оно открыто. | авто |
| 4.13 | **[жел.]** Если в «Кому» и «Копии» вместе больше 10 получателей, шапка письма показывает их свёрнутыми: в каждой строке три первых по имени и «и ещё N», полный список — во всплывающей подсказке. «и ещё N» разворачивает обе строки, «Свернуть» в конце последней сворачивает (`aria-expanded`, с клавиатуры тоже); каждое письмо открывается свёрнутым. Короткие списки показываются целиком, как раньше; так же в отдельном окне письма и во вложенном письме (`.eml`) во встроенном просмотрщике. | авто, ручн. |
| 4.14 | **[жел.]** Текст письма любого вида (обычный текст, HTML, Markdown) лежит на одной карточке: рамка, скругление и отступы одинаковые, переключение «HTML · Markdown · Текст» меняет только содержимое. Обычный текст и Markdown — в цветах темы, смена темы перекрашивает их сразу; строка обычного текста не длиннее примерно 72 знаков. HTML остаётся на белом во всех темах: цвета письма задаёт отправитель. Так же выглядит вложенное письмо (`.eml`) во встроенном просмотрщике. | ручн. |

## 5. Отправка (SMTP)

| № | Критерий | Проверка |
| --- | --- | --- |
| 5.1 | **[обяз.]** Новое письмо, «Ответить», «Ответить всем», «Переслать» (вложения исходного письма сохраняются), цитата исходного текста (в ответе свёрнута под полем ввода, поле открыто сверху), правильные `In-Reply-To` и `References`. | авто |
| 5.2 | **[обяз.]** Вложения выбираются через диалог и перетаскиванием. Если сервер объявил `SIZE`, письмо больше лимита не отправляется, а пользователь видит лимит. | авто |
| 5.3 | **[обяз.]** После отправки копия кладётся в «Отправленные» через IMAP APPEND ровно один раз: Exchange сам её не сохраняет. Если сервер сохраняет сам (Gmail), дубля нет. | авто, Exchange |
| 5.4 | **[обяз.]** Ошибки Exchange переводятся на понятный язык: `421 4.4.2` (лимит 5 писем в минуту) → письмо остаётся в очереди и уходит позже автоматически; `550 5.7.60` → «нет права отправлять от имени этого адреса»; `535 5.7.3` → «неверный логин или пароль»; `530 5.7.57` → «сервер требует входа»; `552` → «письмо слишком большое». | авто (фейковый SMTP), Exchange |
| 5.5 | **[обяз.]** Неотправленное письмо не теряется: при ошибке оно остаётся в «Исходящих» клиента, при закрытии окна написания — в «Черновиках» на сервере. | авто, ручн. |
| 5.6 | **[обяз.]** Скрытая копия не попадает в заголовки, ни у получателей, ни в «Отправленных». | авто |
| 5.7 | **[жел.]** Несколько подписей на учётную запись, одна из них по умолчанию; можно не иметь ни одной. Список — в разделе «Письма и подписи» страницы ящика, в меню «⋯» карточки: изменить, переименовать, сделать по умолчанию, сделать по умолчанию для ответов, выше и ниже (и перетаскиванием), удалить. Подпись пишется тем же визуальным редактором, что и письмо: оформление, ссылки, картинки из файла и из буфера; копия картинки хранится вместе с подписью, исходный файл не нужен; картинки тяжелее 200 КБ вызывают предупреждение. Текстовая версия получается сама: текст и ссылки с адресом, без картинок. В письме подпись — отдельный блок под текстом, над цитатой, править его нельзя; меню на самом блоке выбирает другую подпись ящика или «Без подписи», после чего остаётся тихая строка «Без подписи · добавить». Смена отправителя ставит подпись нового ящика по умолчанию. Ответы, «Ответить всем», пересылка и быстрый ответ получают подпись по умолчанию для ответов, когда она задана, иначе — обычную подпись по умолчанию; новое письмо — обычную. HTML-письмо уносит картинки подписи частями `multipart/related` с `Content-ID`, без внешних адресов; в письме обычным текстом подпись — текстовая версия под «-- ». В Markdown-письме подпись оформлена так же, как в HTML (оформление и картинки, в окне — отдельным блоком, а не текстом под «-- »), и адресат получает её в трёх частях — `text/plain`, `text/html` и `text/markdown`. Текстовая подпись, сохранённая до обновления, становится подписью по умолчанию с тем же текстом. | авто, e2e, ручн. |
| 5.8 | **[жел.]** Подсказка адресов из уже полученных и отправленных писем. | ручн. |
| 5.9 | **[жел.]** Письмо пишется обычным текстом, в HTML (полужирный, курсив, подчёркивание, списки, ссылка, цитата, картинки) или в Markdown (правка прямо в тексте, как в Obsidian: жирный, курсив, подчёркивание, списки, ссылка, цитата; заголовок, код и таблица — в «⋯» строки оформления; таблица правится в ячейках, ручки строк и столбцов вставляют, выравнивают, удаляют и двигают, широкая таблица прокручивается вбок). Формат показывает и меняет кнопка в нижней панели рядом с «⋯» (HTML · Markdown · Текст, текущий с галочкой; подпись кнопки называет режим, в узком окне — только значок), там же «Сохранить черновик» `Ctrl+S` и «Удалить черновик»; строка оформления — под темой; в узком окне её редкие кнопки уходят в свой «⋯». Формат новых писем задаётся в настройках «Почта» (на новой установке — HTML, у настроенной до обновления — обычный текст), у ящика может быть свой; смена в окне письма касается только этого письма. Подтверждение спрашивается только при переходе HTML → «Текст», если есть что терять; остальные переходы — тостом с «Отменить». Картинка вставляется кнопкой «Картинка» (из файла или из буфера), через Ctrl+V и перетаскиванием на зону «Вставить в текст» и в HTML, и в Markdown; крупное фото уменьшается до порога (по умолчанию 1600 px, настройка «Почты»), у картинки два размера: по ширине текста и исходный; в Markdown её разметка видна под курсором, описание — это `alt`. Обычный текст уходит одной частью `text/plain`; HTML и Markdown — `multipart/alternative` из `text/plain` и `text/html` одного содержания, у Markdown между ними ещё сам исходник `text/markdown; variant=CommonMark` (о составе частей говорит тихая строка под текстом), картинки — в обоих случаях частями `multipart/related` с `Content-ID`, а не вложением. Блоки кода подсвечиваются на клиенте и в редакторе, и при показе Markdown-письма (в уходящем HTML подсветки нет). Ответ в HTML содержит цитату с оформлением внутри текста, подпись стоит над цитатой и меняется при смене отправителя. Быстрый ответ — простое поле, уходит в формате ящика; его высота меняется ручкой в правом верхнем углу (вверх — выше, с клавиатуры стрелками). Развёрнутый в окно быстрый ответ сохраняет пустую строку между набранным текстом и подписью, и курсор встаёт в неё. Недописанный быстрый ответ при переходе к другому письму сохраняется в черновики без окна, сообщение предлагает открыть его; если сервер не принял черновик, он ждёт в свёрнутом окне с ошибкой. `Esc` уводит быстрый ответ в свёрнутое окно. Формат, оформление и картинки сохраняются в черновике на сервере и в «Исходящих». Вставленный HTML очищается, внешние картинки при вставке не загружаются. | авто, ручн. |
| 5.10 | **[жел.]** Ящик по умолчанию применяется к новым письмам: если он задан в настройках «Почта», новое письмо всегда создаётся от него, даже когда открыта папка другого ящика; «По контексту» берёт ящик из открытой папки или письма, иначе — первый. Удалённый ящик трактуется как «не задано». Ответы, «Ответить всем», пересылка и быстрый ответ уходят от ящика-получателя независимо от настройки. | авто, ручн. |
| 5.11 | **[жел.]** Поле набора HTML-письма и редактор подписи — белый лист в карточке во всех темах, как письмо выглядит у адресата: цвета листа задаёт отправитель. Обычный текст и Markdown остаются в цветах темы, смена темы перекрашивает их сразу. | ручн. |
| 5.12 | **[жел.]** Копия отправленного письма, которую сервер отвергает насовсем (ящик переполнен, лимит размера, нет папки «Отправленные», `NO`/`BAD` на APPEND), не гоняется вечно: отказы считаются отдельно от сетевых сбоев, пауза между ними 30 мин → 2 ч → 6 ч, после третьего копия встаёт на паузу и письмо больше не загружается. В «Фоновых задачах» появляется задача простыми словами и с ответом сервера, у ящика в боковой панели — значок, при запуске, пока копия не решена, — тост. Действия: «Повторить» (сбрасывает счёт и пробует сразу), «Сохранить .eml» (копия остаётся) и «Не сохранять копию» (запись удаляется). Сбой сети и таймаут повторяются, как раньше. | авто, e2e |

## Сценарий ручной приёмки на Exchange 2019

Нужен тестовый ящик на Exchange 2019 с включённым IMAP4 и SMTP-submission. Предусловия на сервере: запущены службы `MSExchangeIMAP4` и `MSExchangeIMAP4BE`; у ящика `ImapEnabled = True`; на receive-коннекторе `Client Frontend` назначен сертификат, то есть STARTTLS есть.

1. Добавить ящик мастером: адрес → автоопределение → вход. Ожидание: найден `mail.<домен>`, 993 TLS и 587 STARTTLS, вход успешен. (1.1, 1.2, 2.1)
2. Повторить с логином `ДОМЕН\пользователь`. (1.5)
3. Проверить папки: русские имена, роли, служебные папки скрыты. (3.1–3.3)
4. Отправить из OWA три письма: UTF-8, Windows-1251, с вложением и картинкой в теле. Ожидание: появляются без ручного обновления меньше чем за минуту, читаются корректно. (3.5, 4.2–4.5)
5. В OWA пометить письмо прочитанным и перенести другое в папку. Ожидание: изменения видны в Депеше. (3.7)
6. Ответить, ответить всем, переслать с вложением. Ожидание: письма доставлены, в OWA цепочка собрана, копия в «Отправленных» одна. (5.1, 5.3)
7. Отправить 7 писем подряд. Ожидание: после пятого `421 4.4.2`, оставшиеся уходят автоматически. (5.4)
8. Отправить от чужого адреса. Ожидание: понятная ошибка про права, письмо не потеряно. (5.4, 5.5)
9. Удалить письмо, затем удалить его из «Удаленных». (6.1)
10. Оставить клиент на 40 минут, затем отправить письмо из OWA. Ожидание: письмо появилось без перезапуска. (3.5, 3.6)
11. Отключить сеть на 2 минуты и включить. Ожидание: синхронизация восстановилась сама. (3.6)
12. Если сервер отдаёт просроченный или самоподписанный сертификат: понятное предупреждение и доверие конкретному отпечатку. (2.2)
13. Найти поиском на сервере письмо старше 500 последних. (6.5)
14. Ответить, ответить всем и переслать три письма из Депеши. Ожидание: значки сразу; в OWA у писем те же отметки (ответ, ответ всем, пересылка). Ответить всем в OWA на четвёртое: после синхронизации в Депеше значок «ответ всем» с подсказкой «отметка сервера, время неизвестно». (6.7)
15. Включить «Убирать письмо из входящих, пока не ответят» и ответить на письмо из «Входящих». Ожидание: через 10 секунд цепочка в папке «Ждут ответа», в OWA тоже; «Оставить во входящих» возвращает её. Ответить ещё раз и написать ответ из OWA другого ящика: письмо вернулось во «Входящие» с меткой «пришёл ответ», автоответ «Нет на месте» его не возвращает. (6.8)

## Сценарий ручной приёмки: Exchange 2019 только с OWA (EWS)

Нужен ящик на Exchange 2019, у которого снаружи опубликованы OWA и `/EWS/Exchange.asmx`, а IMAP и SMTP закрыты. На виртуальном каталоге EWS включена Basic-авторизация (`Get-WebServicesVirtualDirectory | fl BasicAuthentication`).

1. Мастер → «Exchange без IMAP (только OWA)…» → адрес, `ДОМЕН\пользователь`, пароль, поле сервера пустое. Ожидание: адрес EWS найден через Autodiscover, вход успешен.
2. Повторить, указав в поле сервера адрес OWA `https://mail.<домен>/owa`. Ожидание: подставлен `https://mail.<домен>/EWS/Exchange.asmx`.
3. Неверный пароль. Ожидание: «неверный логин или пароль», ящик на паузе, повторных попыток нет.
4. Папки: «Входящие» с подпапками, «Отправленные», «Удаленные», «Нежелательная почта» с ролями; календарь, контакты, задачи и «Исходящие» скрыты.
5. Письмо из OWA появляется меньше чем за минуту без ручного обновления; прочтение и перенос в OWA видны в Депеше после синхронизации.
6. «Загрузить старые» в папке с больше чем 500 письмами догружает следующие 200.
7. Ответить, переслать с вложением, отправить со скрытой копией. Ожидание: письма доставлены, получатель Bcc получил письмо, копия в «Отправленных» одна (её кладёт сервер).
8. Отложить письмо до времени через 2 минуты. Ожидание: вернулось во «Входящие» непрочитанным.
9. Удалить письмо, затем удалить его из «Удаленных».
10. Поиск на сервере находит письмо старше загруженного окна.
11. Если Basic на EWS выключен: понятная ошибка с командой для администратора.

## Сценарий ручной приёмки: вход через Google, Яндекс и Microsoft

Нужна сборка с OAuth-клиентами (переменные `DEPESHA_*_CLIENT_ID`) или клиенты, указанные в настройках.

1. «Войти через Google» → в браузере выбрать аккаунт и разрешить доступ. Ожидание: вкладка пишет «Вход выполнен», ящик добавлен и синхронизируется, отправка работает, копия в «Отправленных» одна.
2. То же для Яндекса (в настройках Яндекс Почты включён IMAP с авторизацией по OAuth-токенам) и для Microsoft (Outlook.com или Microsoft 365 с разрешённой авторизацией SMTP).
3. Отозвать доступ приложения в настройках аккаунта провайдера. Ожидание: ящик на паузе с ошибкой «войдите заново»; «Исправить» → «Войти заново» возвращает работу без удаления ящика.
4. Закрыть вкладку браузера, не входя. Ожидание: «Отмена» в мастере прерывает ожидание; кнопки других провайдеров всё это время доступны, щелчок по одной из них прерывает ожидание и открывает её вход. После отмены или ошибки строка «Ждём ответа … из браузера…» пропадает, повторный вход тем же провайдером работает.
5. Перезапустить Депешу. Ожидание: повторный вход не нужен, токен обновляется сам.
6. «Войти через Google» и на странице разрешений не отметить доступ к Gmail. Ожидание: мастер сразу пишет «Google не дал доступ к почте…», ящик не сохраняется.
7. Сборка без клиента какого-то провайдера. Ожидание: кнопки этого провайдера в мастере нет; без единого клиента блока входа через браузер нет вовсе.

Google-клиент для сборки: в Google Auth Platform создать клиент типа Desktop app; в Data access добавить `https://mail.google.com/` (restricted), `openid`, `.../auth/userinfo.email`, `.../auth/userinfo.profile`; пока приложение в режиме Testing, адрес должен быть в Test users, а токены живут 7 дней. Google спрашивает согласие на каждый scope отдельно: на странице разрешений доступ к Gmail надо отметить.
